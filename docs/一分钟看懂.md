# 一分钟看懂：这个项目到底在干什么

## 场景（真实存在的工作）

游戏里所有活动都是策划填表配出来的：活动叫什么、什么时候开、奖励哪一组道具、权重多少、几级能参加。
表是 CSV/Excel，改完导出，程序读进去。

**问题**：填错了程序不会拦你，进游戏才暴露。常见的三种错：

| 错误 | 进游戏后什么样 |
|---|---|
| 结束时间早于开始时间 | 活动永远不出现，策划以为上线了 |
| 奖励组写了个不存在的 `RG-09` | 玩家领奖时崩，或者发空奖励 |
| 两个同类活动时间重叠 | 奖励被重复发，运营事故 |

人工看表能发现，但 200 行 × 30 列没人看得住。
**这个项目就是：写一个程序，自动把这些错挑出来，并且人话告诉你哪里错了。**

## 一句话

> **把"策划填的表"交给"你写的程序"，程序照着"一份规则清单"逐项检查，输出"哪里错了、怎么改"。**

## 安检类比（记住这个就懂了）

| 现实 | 本项目 |
|---|---|
| 旅客行李 | `data/*.csv`（策划填的表） |
| 安检规则（液体≤100ml、不许带刀） | `config/rules.yaml`（12 条规则） |
| 安检员 | `config_forge/validator.py`（你写的检查程序） |
| 违规行李贴条 | `report.json` / 控制台报错 |
| 帮你打包的人（快，但会装违禁品） | LLM：把一句话需求变成配置草稿 |

**关键**：安检规则是**可配置的**——明天加一条"活动奖励不能超过 5 件"，改 YAML 就行，不改代码。
这就是"规则引擎"的全部含义，没别的玄学。

## 最后跑起来是什么样（目标画面）

```
$ python -m config_forge.cli --schema config/schema.yaml --data data --out report.json
config-forge v0.1 · 12 条规则 · Mock 模式

activities (5 行)
  [error] R01 ACT-0003：name 不能为空
  [error] R04 ACT-0003：weight=1.5 超出范围 [0.0, 1.0]
  [error] R09 ACT-0003：end_time(2026-10-04) 早于 start_time(2026-10-05)
  [error] R10 ACT-0003：reward_group=RG-09 在 reward_groups 中不存在
  [error] R11 ACT-0001 与 ACT-0004：同为 festival 且时间重叠
  [warn ] R12 ACT-0002：非节日活动 weight=0.98，体验过强

reward_groups (5 行)
  [error] R07 RG-02 + IT-002：重复（首次出现在第 3 行）
  [error] R10 IT-999 在 items 中不存在

items (3 行)
  ok

汇总：3 张表 / 13 行 / error 8 / warn 1 → 退出码 1
```

**这就是全部目标。** 你写的每一行代码都是为了产出上面这段输出。

## 你最终要写的 7 个文件（各自的活）

| 文件 | 干的事（人话） |
|---|---|
| `loader.py` | 把 CSV 和 YAML **读进来**，变成 Python 的列表和字典 |
| `model.py` | 把 `"0.8"` 这种字符串**变成数字**，`"2026-10-01T00:00:00"` 变成时间；转不动就记一笔错误 |
| `rules.py` | 把规则清单**读进来**，每条规则是一个名字 + 参数 |
| `validator.py` | **逐条规则、逐行数据**地比，发现问题就记一条 `Finding` |
| `report.py` | 把问题**打印出来**、存成 JSON/Markdown |
| `llm.py` | 调 AI 把"国庆做个签到活动"**变成一行配置草稿**（没有 key 用假 AI） |
| `cli.py` | 命令行入口，也就是上面那条 `python -m ...` |

## AI 在这里的位置（别搞反）

- 生成草稿：AI 快，但**会编造不存在的道具 id**（它没看过你的道具表）。
- 校验：**你的程序**，确定性、不放过任何一个。
- 所以这个项目的卖点不是"我用 AI 生成了配置"，而是 **"AI 生成的东西我兜得住"**。后者才是技术策划的能力。

## 为什么这件事值钱（面试一句话）

> "策划配表出错，损失的是运营事故和打包返工。我做的工具让 90% 的低级错误在导进引擎前就被拦住，并且报错文案是策划能直接看懂、能自己改的。"

## 你现在的第一步（30 分钟，不写代码）

打开 `data/activities.csv`、`reward_groups.csv`、`items.csv`，**用眼睛和脑子**把错全找出来，写在纸上。
找完再回头看上面那张"目标画面"——你会发现程序要做的事，跟你刚做的事**一模一样**，只是它不累、不会漏。

这一步叫"人肉校验"，做完你就彻底知道项目在干嘛了。
